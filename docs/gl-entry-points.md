The role of each is the specified one; what it does to CRIME (which registers it writes, which software fallback it takes) is in [opengl.md](opengl.md). Labels: **established** that the symbol is exported (read from the dynamic symbol table) and, in [Derivations from the code](#derivations-from-the-code), which routine each entry point reaches; the role is the published API's, carried out by the routines named there.

## Derivations from the code

Established, N32 `usr/gfx/arch/IP32CRM32/libGLcore.so` (IRIX 6.5.30), full disassembly:

- 498 of the entry points are three-instruction stubs: a load of `$t9` from a fixed address between `0x1050` and `0x17a4` and a jump to it (for example `glFogf` at `0xd931c6c` loads from `0x108c`, `glBegin` at `0xd931594` from `0x106c`). The slots form a per-thread jump table based at `0x1050`; the context pointer the internal routines load sits just below it at `0x1010` (`__gllc_ListBase`, `0xd97d884`).
- Four tables in the library's data have the same layout as the slots: slot address minus `0x1050` is the table offset. `__glcrmim_dispatchTable` holds the CRIME immediate-mode routines and `__glcrmlc_dispatchTable` the CRIME display-list compile routines; `__glPixImmedState` and `__glPixListCompState` hold the pixmap renderer's. The tables were matched by scanning the data sections for words equal to a routine's address. Spot checks: `glBegin` (offset `0x1c`) reaches `__glcrmim_Begin`; `glAlphaFunc` (offset `0x198`) reaches `__glcrmim_AlphaFunc`; `glFogf` (offset `0x3c`) reaches `__glim_Fogf` in both immediate tables, so fog parameters have no CRIME-specific entry.
- The tables are installed by copying. `__glPixmapMakeCurrent` copies its table with a doubleword loop (`0xd9940d0..0xd994158`) and uses `0x1050` as an immediate (`0xd994220`). Only `MakeCurrentRead` and `__glCrmCreateContext` reference the CRIME tables. That `MakeCurrentRead` copies them the same way is inferred from the shared offsets; its copy loop was not traced.
- 57 entry points, all from `so_stubs.c`, are two-instruction routines that return at once: the extension is exported but does nothing on this build. The 16 vector forms of the multitexture coordinate entry points listed above are routines in `so_vertarray.c` that the debugging information names but the dynamic symbol table does not export.

So an entry point's role is the routine in its row. The CRIME routine is the one that reaches the hardware ([opengl.md](opengl.md)), and the pixmap routine is the software path for rendering into pixmaps. Where both immediate tables name the same `__glim_` routine, the operation is device-independent state or a query.
