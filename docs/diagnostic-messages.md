# CRIME, MACE and GBE diagnostic messages

Text the O2 graphics kernel code prints, or passes to its error reporter, and where each message is printed. Each entry names the routine that prints the message, its object and start address, the call and the condition on the path, and a label. The routines come from the shipped IRIX 6.5.30 kernel objects in `usr/cpu/sysgen/IP32boot/`: `crime.a` members and `mace.o`.

Addresses are offsets from the start of the member's `.text` section, as `objdump -dr` shows them for the relocatable object. `cmn_err` is the kernel's message routine; its first argument is the level and the second the format. A message prints only on the path named.

Labels: **established** means read from the instructions of that path; **inferred** means a reasoned reading that the code does not state; **unknown** means the text names something the code does not show.

## Kernel driver messages

- `crimeFifoEmptyHandler` (`usr/cpu/sysgen/IP32boot/crime.a(crime.o)`, 0x0) prints `Unexpected empty interrupt with code %d` at 0x110. **Established.** The code is the word at the handler's argument +544 (0x220), loaded at 0x8. The message prints on the path where that word is neither 2 (branch at 0x20) nor 1 (branch at 0x28). The level argument is 5.

- `crimeFifoFullHandler` (`usr/cpu/sysgen/IP32boot/crime.a(crime.o)`, 0x1a8) has two messages. It prints `Cfifo Overflow! Current level at %d (ctl 0x%x)` at 0x348, level argument 0. **Established.** The path is entered from the branch at 0x1d0 when the FIFO level field is 65 or more. The field is bits 18 to 24 of the word at the CRIME register block +0x4000 (loads at 0x1b4 to 0x1bc). The second printed value is `level - 1`, stored at 0x334 (`addiu a2,v0,-1`). The third is the word at +0x400 (load at 0x344). The register block pointer comes from the handler's argument at +120 (0x1b0). **Inferred:** that the field counts FIFO entries, as the text says. It also prints `unexpected fifo full interrupt` at 0x360, level argument 0. **Established.** Taken when the word at the handler's argument +60 (0x3c) is nonzero (test at 0x2d8, branch at 0x2dc to 0x358). The message has no argument; the path then rejoins the main flow at 0x2e8.

- `crimeEmptyWaitTimeout` (`usr/cpu/sysgen/IP32boot/crime.a(crime.o)`, 0x120) passes `fifo callback` as the second argument of the `crimeError` call at 0x160. **Established.** The path is taken when the word at +544 (0x220) is nonzero (test at 0x138 and 0x13c). The string completes the message printed by `crimeError` below.

- `crimeError` (`usr/cpu/sysgen/IP32boot/crime.a(crime.o)`, 0x57d4) prints `crimeError: resetting graphics from %s` at 0x57f0, level argument 4. **Established.** Printed on every call. The `%s` argument is the caller's second argument (moved to a2 at 0x57d4). After the message the routine waits 10 units, clears the word at +1032, and flushes the bus. Known caller: `crimeEmptyWaitTimeout`, with `fifo callback`.

- `crimeFifoWaitTimeout` (`usr/cpu/sysgen/IP32boot/crime.a(crime.o)`, 0x2b34) prints `Cfifo wait timeout.` at 0x2b4c, level argument 4. **Established.** This is the first action of the routine. `crmFifoWait` registers it as the timeout callback (`timeout` call at 0x2d1c with the address of `crimeFifoWaitTimeout`). After the message the routine disables interrupt 25 and sets the word at +548 (0x224) of its argument to 1.

- `crmFifoWait` (`usr/cpu/sysgen/IP32boot/crime.a(crime.o)`, 0x2b94) prints `crime fifo timeout after 0x%x us` at 0x2dac, level argument 4. **Established.** The value printed is the third argument on entry (saved in s4 at 0x2bcc, moved to a2 at 0x2da4). Two routes reach it, both through the test of the word at +548 (0x2c80). The first needs the halfword at `.data` +60 to be zero (test at 0x2c4c) and the register `ra`, set by the `slt` at 0x2c50, to be zero (branch at 0x2c74): the routine then stores 1 to +548 (0x2c7c) and prints. The second is the sleep path taken when `ra` is nonzero (0x2c90): after `sv_wait` returns, the word at +548 is reloaded (0x2d98) and prints if `crimeFifoWaitTimeout` has set it. **Inferred:** that `ra` is set when the requested count is no more than the 100 spin passes, so the first route prints when the whole wait was spent polling; the code does not name it.

- `crmIdleWait` (`usr/cpu/sysgen/IP32boot/crime.a(crime.o)`, 0x2dbc) prints `crime idle timeout after 0x%x us` at 0x2e44, level argument 4. **Established.** The value printed is the second argument on entry, saved at sp+8 (0x2dc0) and reloaded at 0x2e40. The message prints when the countdown in s0 (set from that argument at 0x2dd8) reaches zero at the test at 0x2e1c. Each pass calls `us_delay` with 1. The loop exits early with no message when bit 28 of the word at the CRIME register block +0x4000 is set and the FIFO level field is zero (tests at 0x2df4 and 0x2dfc). **Inferred:** that the count is in microseconds, as the text says.

- The FIFO wait timeout sequence (`crime.o`, `crmFifoWait` 0x2b94 to 0x2db8, `crimeFifoWaitTimeout` 0x2b34, `crimeError` 0x57d4, strings in `.rodata`). The wait polls first and sleeps second; the messages come out in a fixed order.
  1. **Established.** The poll: unless the halfword at `.data` +60 is non-zero, the requested count is capped at 100 (`li s5,100` at 0x2c68), then the routine reads the level field (bits 18 to 24 of the status word at +0x4000, `0x2c0c` to `0x2c1c`) and calls `us_delay(1)` between reads, up to that many times. The target level is a kernel global word (the same value `crimeError` writes into all four threshold fields of the control word) minus the second argument; the routine returns 0 as soon as the level is no higher than that target. If the halfword at `.data` +60 is non-zero the cap is not applied and the whole request is polled.
  2. **Established.** When the poll runs out and the capped count is not below the requested count (the `slt` at 0x2c50), the wait was all poll: it stores 1 to the timed-out word at +548 and prints `crime fifo timeout after 0x%x us` straight away (0x2c7c, 0x2da4). This route is taken by any request of 100 or fewer.
  3. **Established.** Otherwise it sleeps. It sets the interface-buffer empty threshold (bits 14 to 20 of the control word) to the target level and writes the word to +0x400 (0x2cb4 to 0x2cd8), arms `timeout` with `((request - 100) / 1000000) * 100 + 100` ticks (the `div` by `0xf4240` at 0x2cf4 and the `ori a2,a2,100` at 0x2d1c, with the `teq` trap for a zero divisor), enables CRIME input 25 and sleeps on the semaphore at +556. Both `0xf4240` (used by `crmFreeTiles`, `crmSavePP`, `crimePcxSwap`, the retrace path) and `0x1000` (used by `crimeInitHW`) are below 2,000,000, so the quotient is 0 and **both arm 100 ticks**: the nominal request does not change the sleep. Whether 100 ticks is one second depends on the kernel tick rate, which this object does not state; the neighbouring `_cpuclkper100ticks` calibration suggests 100 ticks per second (**inferred**).
  4. **Established.** If the empty interrupt (input 25, `crimeFifoEmptyHandler`) wakes the sleeper first, the handler cancels the timeout and the wait returns 0 with no message. If the timeout fires first, `crimeFifoWaitTimeout` prints `Cfifo wait timeout.`, disables input 25, sets the timed-out word and wakes the sleeper; the sleeper then restores the threshold, reads the timed-out word and prints `crime fifo timeout after 0x%x us` with the original request. So on a stalled FIFO the order is `Cfifo wait timeout.` then `crime fifo timeout after 0xf4240 us`, about 100 ticks after the wait started plus up to 100 microseconds of poll.
  5. **Established.** What happens next depends on the caller. `crmSavePP` (called for a context save) and the swap paths test the return value and call `crimeError` with the text `SavePP`, `PcxSwapOut` or `PcxSwapIn` (the latter two after a `crmIdleWait`, which has the same 0xf4240 request): the third message is `crimeError: resetting graphics from SavePP`, followed by the engine reset described in [reset.md](reset.md#error-recovery-kcrimecrimeerror). `crmFreeTiles` (request `0xf4240`) and `crimeInitHW` (request `0x1000`) ignore the return value (decompilation and the `jal` sites), so they print the two wait messages and carry on without a reset.


- `crmSwapBufd` (`usr/cpu/sysgen/IP32boot/crime.a(crime_retrace.o)`, 0x1cdc) prints `crime: swapbufd cannot context switch` at 0x20d8, level argument 1. **Established.** Reached when `RRM_CheckValidFault` (call at 0x1e54, first argument the routine's own first argument; no second argument is set before the call) returns a negative value (`bltz` at 0x1e5c). The path first calls `mrunlock` (0x20c8), then prints.

- `crimeSchedSwapBuf` (`usr/cpu/sysgen/IP32boot/crime.a(crime_retrace.o)`, 0x20f0) prints `crimeschedswapbuf: wid %d already swapping buffers` at 0x22c0, level argument 4. **Established.** The `%d` is the third argument on entry (wid, in a2); the routine never writes that register. The window index must be 0 to 31 (tests at 0x2104 and 0x2110; out of range returns 22 at 0x21e8). The message prints when the byte at (table + 24 x wid + 56) is nonzero, where the table pointer is the word at the first argument +140 (tests at 0x2124 and 0x2128). The return value on this path is 16 (`li v0,16` in the delay slot at 0x22cc). It has a second message, `crimeschedswapbuf: wid %d pending`, printed at 0x22d8 with level argument 4. **Established.** The `%d` is again the third argument (wid). Two branches reach it: from 0x21f4 after the state word of the window record (+36, masked with 0x1c) is 4 or 16 (branches at 0x2150 and 0x2158) and the board-type byte (+47 of the word at the first argument +124) is not 32; and from 0x2248 when that byte is 32 and either the masked state is 20 (0x222c) or the byte at +58 is nonzero (0x2234). Both need bit 1 of the byte at +57 set (tests at 0x21f0 and 0x2244). The return value is 16 (`li v0,16` at 0x22e4).

- `crimeSchedMgrSwapBuf` (`usr/cpu/sysgen/IP32boot/crime.a(crime_retrace.o)`, 0x2484) prints `crimeSchedMgrSwapBuf: WID %d already swapping buffers` at 0x25a4, level argument 4 (0x2598). **Established.** The `%d` is the third argument on entry (moved to a2 at 0x259c). The message prints when the byte at (table + 24 x wid + 56) is nonzero (test at 0x24d0 and 0x24d4); the table pointer is the word at +140 of the record at the first argument +24 (loads at 0x249c and 0x24b0). The path is entered only after `RRM_CheckValidFault` (call at 0x24ac) returned a non-negative value, because a negative value returns -14 (0x2594). The return value on the message path is 16 (0x25b0).

- `crmDestroyPbuffer` (`usr/cpu/sysgen/IP32boot/crime.a(crime_tiles.o)`, 0xf5c) prints `crm memory leak in destroypb` at 0x1024. **Established.** Reached when `psema` (call at 0xf7c, on the word at ([[s0+32]+28]+4)) returns nonzero (branch at 0xf84). The level argument is 4: the `li` at 0xf88 sits in the delay slot of the branch at 0xf84 and runs on both paths. The path frees nothing and returns, while the fall-through path frees the chunks. **Inferred:** that the text names a leak is a guess from the message; the path's visible effect is a failed semaphore wait.

- `crime_i2cFpHotProbe` (`usr/cpu/sysgen/IP32boot/crime.a(crime_i2c.o)`, 0x16d8) prints `\ncrime_i2c: ERROR! Hot Probe of 7of9/DCD not allowed` at 0x1860, level argument 4. **Established.** The message starts with a newline. The path is taken when the byte at the probe state +46 equals 132 (test at 0x1708), or when the byte at +44 is nonzero (test at 0x1714). The probe state pointer is the word at the argument +124 (0x16e8). **Inferred:** that DCD is the dual-channel display option, whose option-hardware name `O2_DCD` [gbe.md](gbe.md) records; the message text and the code do not say it. **Unknown:** what 7of9 names.

- `mace_stray` (`usr/cpu/sysgen/IP32boot/mace.o`, 0x178) prints `mace_stray() interrupt - CRIME int = %d` at 0x190, level argument 4. **Established.** The `%d` argument is the address of the external symbol `intr` (`addiu` at 0x194, not a load), so the printed number is that address, not an interrupt number. The routine does nothing else. **Inferred:** that the author meant the interrupt number; the code passes the address.
