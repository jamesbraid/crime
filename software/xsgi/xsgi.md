# The X server (`Xsgi`): board bring-up and the resource-manager layer

The board-independent X server [`Xsgi`](../../root/usr/gfx/arch/GENERIC/Xsgi) (IRIX 6.5.30, `usr/gfx/arch/GENERIC/`) starts the graphics board for the board module [crm.so](xmodule.md), keeps the resource-manager records of window IDs and clip IDs, and carries the double-buffer extension. This page holds the routines of the server that sit on the path to the O2 graphics driver. Each entry was written after reading the whole body in the decompilation of the server (Ghidra, gp recovered from the prologues), and gives the routine's offset and size. **Established** means every branch and store stated was read; **Inferred** means a part of the body was followed in outline. The server has no symbols for file-local routines, so those carry the compiler suffix of two dots and letters.

## Board bring-up

- `irixKernInit` in `Xsgi`: attaches a graphics board to the server and returns its handles, 1008 bytes at offset 0x10124250. It is called by the board module's kernel-init routine with the generation, the board number, an optional base address and four output pointers. After the first call for a board it returns the four cached values. Otherwise it opens the graphics control device with flags 0x802, attaches the board with request 0x67 carrying the board number and an address (the caller's base, or the module's default board base, plus the board number times the module's board size), opens the graphics device, creates a rendering node with request 1000, binds it with request 0x3ea, labels the board with request 0x6f and a string made from the display name and the screen number, and links the graphics device's event stream to the resource-manager event routine. It stores the stream link, the control descriptor, the node and the board address in four per-board tables, one word per board, that start at 0x102d0c00 and lie 0x40 bytes apart, and returns them through the output pointers. Each failing step prints a message and returns false. Established.
- `ddxGetBoardInfo` in `Xsgi`: returns the entry of the server's board-information table for the board index it is given, 28 bytes at offset 0x100efe60, and does nothing else. Established.
- `ddxGetBoardName` in `Xsgi`: copies the name held in the board-information entry for an index into the caller's buffer in lower case, at most fifteen characters, and ends it with a zero byte; it returns false for an index at or above the board count and true otherwise, 240 bytes at offset 0x1012a250. Established.
- `AllocateScreenPrivateIndex` in `Xsgi`: makes room for one more per-screen private pointer, 428 bytes at offset 0x10172080. It adds one to the module's private count and then resizes the private array held at +0x1b4 of every screen record to the new count, with `realloc` or a fresh allocation, failing with a fatal error when memory must be had and otherwise undoing the increment and returning -1. The result is the index that was free before the call. The board module and the resource-manager layer each take one such slot. Established.
- `ddxOpenScreens` in `Xsgi`: opens every requested screen and links the screens side by side, 1612 bytes at offset 0x1012cb60, whole body read from the decompilation. With no screen requested it asks the board-request routine for boards and returns false when that finds none. For each entry of the 24-byte requested-screen table it fills in zero default colormap bytes from the server's two default settings; when the entry names neither a board type nor a board number it enumerates boards once if none are known and takes the first board number no other entry claims, copying that board's name, and when it names a type it takes the first board of that type. It then finds the board module: for a screen whose load-type byte is 2, or is not 1 while the server default is not 1, it looks for an already loaded module of the same name, otherwise builds the module path, loads the shared object by the dynamic loader, resolves the symbol made from the module name and the word for screen information, reports each failure through the server's error printer and unloads the object on failure. It calls the module's first function with 3 and the table entry, copies the 0x4c-byte screen record into a fresh block, points both records at the table entry and appends the copy to the active-screen array. A failure prints that the board could not be loaded, with its number and type. When an earlier screen opened, the new one is joined to it through the neighbour bytes of the table entries, right link of the earlier and left link of the new in the side-by-side layout, the vertical pair when the server runs stacked, only when the new entry has no explicit connection. It finishes by clearing the current-screen word and returns true when at least one screen is active. Established.
- `ddxPostOpenScreens` in `Xsgi`: lays the opened screens out on one desktop, 1452 bytes at offset 0x10198910, whole body read from the decompilation. It first copies each active screen's width and height halfwords (+0x18 and +0x1a of the screen record) into a local table. For each screen it then follows the left-neighbour link (the byte at +0x12 of the screen's table entry) from screen to screen, marking each as visited so a loop stops it, adding the widths seen, and stores the sum as the screen's x origin and the sum plus its own width as the x end in its table entry; the same walk along the upper link (the byte at +0x14) gives the y origin and end from the heights. The wrap-around options then close the layout. With the horizontal wrap on and the side-by-side layout it joins the last screen's right link to the first and the first's left link to the last when neither is already set; when the server runs stacked it gives each unlinked screen links to itself in both directions. With the vertical wrap on it does the opposite: in the side-by-side layout each unlinked screen gets vertical links to itself, and in the stacked layout the last and first are joined vertically. A link that was already set prints a message that the explicit connection conflicts with the wrap option, naming the screen in the per-screen case. Established.

## Resource-manager records

- `rrmInit` in `Xsgi`: sets up the resource-manager record of one screen, 952 bytes at offset 0x101ec4d0. The first call of a server generation takes a screen private index and a window private index (stored in module globals). Each call allocates a record of 0x98 bytes plus 36 bytes for every window-ID entry the caller's template names in its first word, stores it in the screen's private array, copies the first 47 words of the template, and swaps six screen hooks (at +0xc4, +0xc8, +0xb4, +0xb8, +0xe0 and +0xcc) with the template's replacements while keeping the old ones in words 0x1a to 0x1f of the record. It zeroes the entry table, clears one halfword in each entry, calls the template's initialiser at word 0x15 when there is one, and, when the template names clip IDs, calls `rrmCIDInit..DFC`. It returns false on an allocation failure or when the initialiser or the clip-ID set-up fails. Established.
- `rrmCIDInit..DFC` in `Xsgi`: builds the clip-ID table of a screen, 372 bytes at offset 0x100861c0. It allocates 28 bytes for each clip ID named at +4 of the resource-manager record, zeroes the table and stores it at +0x94 of the record. The first entry gets a region covering the whole screen (made with the screen's region-init method at +0x154) and the halfwords 5 at +8 and 0 at +10; every other entry gets an empty region. It then calls the record's hook at +0x58 when set (a zero result is a failure), clears +0x88 and returns true. Established.
- `rrmSetReservedDID` in `Xsgi`: marks one window-ID entry of the resource-manager record as reserved, 84 bytes at offset 0x1015ce50. In the entry (36 bytes apart) it stores 1 at +0xb8, the two words it was given at +0xa0 and +0xa4 and again at +0xb0 and +0xb4, and the halfword 0xd at +0xa8. Established.
- `rrmEvent` in `Xsgi`: handles one word of the graphics event stream, 812 bytes at offset 0x101e9ff0. It gathers the words of a message in a module buffer, taking the word count from the byte at +5 of the first word (limited to 10) and the type from the byte at +6, and complains about a bad count. When the message is complete it takes the low seven bits of the type (1 to 12, otherwise it reports a bogus type) and finds the window: the root window of the screen for identifier 0, otherwise the resource lookup, then the GLX drawable hook of the screen, and with neither it calls the resource-manager screen method at +0x60 and stops. It then calls the handler at the type's slot in the table at +0x80 of the resource-manager record with the window, the high bit of the type and the two payload words, unless a single-client restriction is set and the window belongs to another client, in which case the event is copied into a 28-byte queue node (reporting an allocation failure). Established.

## Double-buffer tickets

- `dbcInit` in `Xsgi`: prepares the double-buffer extension, 176 bytes at offset 0x1010a0a0. If no resource type exists for swap tickets it grows the resource delete-function table by one slot, installs `dbcTicketDelete..IKD` as the delete function and records the new type. It empties the ticket queue and, on the first call, takes a window private index from the module's counter. Established.
- `dbcReset` in `Xsgi`: forgets the ticket resource type and sets the double-buffer window private index to -1 at server reset, 28 bytes at offset 0x100f5f60. Established.
- `dbcTicketDelete..IKD` in `Xsgi`: the delete function of a swap ticket, 140 bytes at offset 0x101afe70. It finds the ticket in the doubly linked queue (front and end pointers kept in the module), unlinks it, fixes the neighbour's back link and the queue ends, and frees it. Established.
- `dbcNoticeSwapInitiated` in `Xsgi`: records that a swap of a window has started, 380 bytes at offset 0x100f31f0. When the byte at +3 of the window's double-buffer private is not 0xff it stores the new buffer number at +2, gives the window a fresh serial number from the global counter (wrapping to 1 past 0x10000000), and walks all clients, resetting the focus-window words at +0x2c to +0x38 of any client record that names this window. Inferred: the client walk was read for one of its unrolled copies only.
- `dbcSwapBuffers` in `Xsgi`: queues a swap request, 712 bytes at offset 0x1010bea0, read as far as the client suspension. It allocates a ticket of 24 bytes plus 4 per window, stores each window's requested buffer in the byte at +3 of its double-buffer private and its identifier in the ticket, makes a fake client identifier and registers the ticket as a resource of the swap-ticket type (failing with an allocation error when that fails), appends the ticket to the queue, raises the yield flag and counts it, and then removes the client from the server's ready and input masks so that it sleeps until the swap is done. Inferred: the handling of clients that use the low-bandwidth extension was not read.
- `dbcSetDrawBuffer` in `Xsgi`: chooses which half of a double-buffered window drawing goes to, 1092 bytes at offset 0x1015c520, whole body read from the decompilation. When the window has a resource-manager record with bit 3 of its byte at +4 set, it first calls the layer's screen method at +0x20. A window with no multi-buffer record uses the selector byte at +2 of its double-buffer private as the front or back choice: a call with the reset flag clear stores -1 in the draw-buffer byte at +1, and otherwise the choice or its opposite (opposite when the identifier passed differs from the window's own) goes there; an unchanged value returns. A window with a multi-buffer record searches its 24-byte buffer entries for the one holding the identifier passed and takes the opposite of the selector when that entry's index differs from the record's current index, otherwise the selector. Whenever the byte changes the window gets a new serial number from the global counter, wrapping to 1 past 0x10000000, and every client whose focus words name this window has them reset to the root window or to zero. Established.
- `dbcDelayedSwapBufferDone` in `Xsgi`: completes one window of a queued buffer swap, 3008 bytes at offset 0x10098a20, whole body read from the decompilation. It searches the ticket queue for the first ticket whose window list holds the identifier it is given and returns the last ticket when none does. It looks the window up with the security-checked lookup. For a window whose double-buffer private has a swap kind other than 0xff it flips the selector byte, gives the window a new serial number and resets the clients' focus words as the draw-buffer routine does. A viewable window then acts by its kind byte: kind 1 paints the window through the screen's paint method with the draw-buffer byte temporarily set to a reserved value chosen by the selector; kind 2 calls the board method of the nfb screen record when one is installed; kind 3 copies the window onto itself with a scratch graphics context through the copy-area method, after storing the selector and its opposite in the first two bytes, and releases the context, a missing scratch context skipping the ticket's callback. The ticket's callback is then called with the window and the ticket's window count drops by one. A ticket still holding windows has the finished identifier squeezed out of its list. An emptied ticket is unlinked from the queue, its client is allowed to read again by setting its bits in the server's socket and client masks (or clearing the pending flag of an LBX client), and the ticket is freed as a resource through its delete function; a missing resource is a fatal error. The ticket counter then drops by one. Established.

## Screen requests, server options and the multi-screen cursor (read pass 4)

These entries come from the disassembly of the server in the same release, each routine read to its last instruction with the string, global and import names of its slots resolved through the server's global offset table. The server is stripped, so the data words they use have no name of their own. The routines parse the options that select and describe graphics boards, hand the screen and cursor requests to the kernel driver through its control descriptor, and keep the multi-screen cursor bookkeeping; none writes a CRIME or GBE register directly.

- `ddxGetScreenInfo` in `Xsgi`: returns the entry at a given index of the table of active screen records, 28 bytes at offset 0x1022d240. It adds four times the index to the table's address and loads the word there. Established.
- `ddxSetCursorPosition` in `Xsgi`: moves the hardware cursor by an ioctl on the graphics control descriptor, 212 bytes at offset 0x1022a4c0. It builds a four-byte request holding the x and y halfwords and sends it with the request number 0x5308 in a record that carries a command word, a zero, the length four and a pointer to the halfwords. The command is 0xc004510d, named in the message table as the set-all form, when the multi-cursor flag is set and its generation equals the server generation, and 0xc004510a, the single-screen form, otherwise. A negative result prints the warning that the ioctl failed, naming the form that was used. Established.
- `ddxChangeToScreen` in `Xsgi`: switches the active screen, 412 bytes at offset 0x10206210. It returns at once when the index equals the current one. Otherwise it fills the same ioctl record with a set-screen command and the new screen's kernel handle, calls the method at +8 of the old screen's table entry with zero when multi-cursor offsets are in force, sends the request 0x5308, and on failure prints the warning that the set-screen ioctl failed. It stores the new index as the current screen, calls the new screen's switch method when the screen record and the multi-cursor flag allow it, calls the method at +8 of the new screen's table entry with one and the new screen's record, and finally, when multi-cursor offsets are enabled for this generation, calls the routine that restores the default offsets. Inferred: the order of the three method calls and the final test were read, and the record fields are named by their offsets only.
- `ddxMCCursorOn..FEC` in `Xsgi`: a wrapper that records the cursor-on state, 92 bytes at offset 0x100c9900. It finds the multi-cursor saved-method record in the screen's private array (slot index from a module word), calls the saved method at +4 with its argument, and stores that argument in word 0 of the record afterwards. Established.
- `ddxMCCloseScreen..EEC` in `Xsgi`: the close hook of a screen under the multi-screen cursor, 164 bytes at offset 0x1017a2f0. It restores the screen's saved close method at +0x98 from word +0xc of its private record and, when multi-cursor is enabled, also the saved method at +0x11c and the neighbour link word at +8 of the active-screen entry. It frees the private record and calls the restored close method. Established.
- `ddxSetLoadType` in `Xsgi`: reads the dynamic-or-static module option, 144 bytes at offset 0x100cc040. It compares the argument that follows the option, ignoring case, with the option words for dynamic and for static loading, stores the value two for dynamic or one for static in the module's load-type word and returns true; any other text returns false and leaves the word alone. Established.
- `ddxMakeDynamicModulePath` in `Xsgi`: forms the path of a board module, 124 bytes at offset 0x10080080. With a module directory set it writes the directory, a slash, the module name and the shared-object suffix into the caller's buffer; without one it takes the directory from the environment variable that names the dynamic module directory and falls back to the standard dyDDX directory of the X installation. Established.
- `ddxSetIDs` in `Xsgi`: drops the server's privileges after the boards are attached, 200 bytes at offset 0x10190550. When a group id is configured it sets the supplementary group list to that one group, then the group id, and when a user id is configured it calls the security-audit id routine and sets the real and effective user id; each failure prints a message naming the id that could not be set. Established.
- `ddxAddScreenRequest` in `Xsgi`: parses one screen specification after the screen option, 360 bytes at offset 0x1009d430. With no argument it prints that the board specification must follow the option and fails. It sets a local record to its defaults (every board, type and number byte 0xff), lets the screen-argument parser fill it, and appends it as the next 24-byte entry of the requested-screen table, keeping the entry's existing skip byte; a seventeenth screen prints a warning naming the board number and its type, or the word unspecified, and is dropped. It returns 2 on success, the number of arguments used. Established.
- `ddxSetBoardsRequest` in `Xsgi`: parses a comma-separated list of board numbers after the boards option, 860 bytes at offset 0x101ff230. It marks all sixteen requested-screen entries as skipped (the last byte of each 24-byte entry set to one), copies up to 80 characters of the argument, splits it with `strtok` on the list separators, accepts only tokens made of digits, and clears the skip byte of the entry each number names. A token that is not a number clears the skip byte of every entry again and prints that the boards option is bogus. Established.
- `ddxSetVisualRequest` in `Xsgi`: reads the default visual class, 552 bytes at offset 0x101c1d10. It compares the argument, ignoring case, with the twelve spelling pairs of the six visual classes (static gray with both spellings of gray, gray scale, static color, pseudo color, true color, direct color) and stores the class number, 0 for static gray up to 5 for direct color, in the default-class word; unknown text prints a message and fails, a missing argument prints that the class must follow the option. Established.
- `ddxSetColormapDflts` in `Xsgi`: reads the default colormap choices, 480 bytes at offset 0x101ad260. After the pseudo-map option it takes one of the names for the pseudo-color default (1 for the first name, 2 for the environment-map name, 3 for pseudo, 4 for the last) and stores it in one module word; after the static-color option it takes the name for the OpenGL map (stored as 32) or the cube (stored as 16) in another word. A missing or unknown name prints what the choices are and fails. Established.
- `ddxInitArguments` in `Xsgi`: registers the two built-in argument tables, 344 bytes at offset 0x10217920. It allocates a 12-byte record for the table named common and another for the table named irix, each linked into the module's list of argument tables (a failed allocation prints a warning that some options may not be recognised), and then clears the first eight words of every 32-byte entry of the module's requested-board table. Established.
- `ddxFindFirstTypedBoard` in `Xsgi`: finds the first board whose type name matches, 324 bytes at offset 0x10289d20. It lower-cases the argument one character at a time into a 15-character buffer and compares it with `strcmp` against the type name of each board record in turn, returning the board index of the first match and 255 when none matches or the board count is zero. Established.
- `ddxRequestBoards` in `Xsgi`: turns the boards the system has into requested screens, 520 bytes at offset 0x101064d0. When no board has been found yet it calls the board finder and stops if that fails. A board count above sixteen prints how many exist and that only the first sixteen are used. For each board whose skip byte is not one it lower-cases the board's type name into a 15-character buffer, duplicates it, and fills the board's 24-byte request entry with the board number and defaults of 255 in the type, number and layout bytes; unless the caller asked for just one it does this for every board, then stores the count in the requested-screen count word and returns whether it is positive. Inferred: the loop was read, the entry byte layout is taken from the stores.
- `rrmCloseScreen` in `Xsgi`: the close hook of the resource-manager layer, 172 bytes at offset 0x102590a0. It finds the screen's record through its private index, returns when there is none, frees the clip-ID table held at +0x94 when there is one (the word at +0x94 read as the table pointer), frees the record itself, and clears the screen's private pointer. Established.
- `rrmUngrab` in `Xsgi`: releases every pending grab of the resource-manager layer, 592 bytes at offset 0x101336c0. For each record of the pending list (the head is a module word, the next link at +0x18) it resolves the window identifier at +8 with the security lookup and, when none is found, the screen's root window from the window table; calls the GLX layer's release method at +0x54 when set, then the resource-manager record's method at +0x60 with the window identifier, hands the record to the free list that the module keeps in a 32-slot ring, and finally calls the screen's method from the table at +0x80 indexed by the record's word at +4, with the three words at +0xc, +0x10 and +0x14. The list head and the two counters are zeroed at the end. Inferred: the loop was read, the roles of the arguments are read from the stores and not from a caller.

- `ddxFindAvailableBoards..CGC` in `Xsgi`: asks the kernel driver which graphics boards exist and gathers each board's description, 972 bytes at offset 0x10082870. It returns true at once when an earlier call has already done the work (a module flag). Otherwise it opens the graphics control device read-write, sends control request 101 to get the board count (a failure prints that it could not get the number of boards and closes the device), and clamps a count above sixteen with a warning. It then walks the boards from the last to the first: request 102 with a 40-byte record asks for the short description and reports the length of the long one at +0x24; it allocates that many bytes (a fatal out-of-memory error when memory must be had, otherwise a message that the allocation failed), asks again with the buffer for the long form and stores the buffer in the board-description table that begins at +0x49e4 of the server's data area. When a module-level device name is set, one more 4096-byte record is built with that name and two halfwords from module words and added as a final board. It closes the device, sets the done flag and returns true. Established.
- `ddxMultiCursorShowHide` in `Xsgi`: keeps the cursor of every screen other than the current one visible only while the pointer is over it, 384 bytes at offset 0x101ac300. It adds the core pointer position to the current screen's origin from the 16-byte per-screen rectangle table and, for each other screen that has a multi-cursor record, compares the position with that screen's rectangle. A screen whose record flag says the cursor is on but whose rectangle does not hold the pointer is hidden by the method at +8 of its table entry called with zero; a screen whose flag is clear and whose rectangle holds the pointer is shown by the same method called with one. Established.
- `ddxMultiCursorDisable` in `Xsgi`: turns the multi-screen cursor off, 428 bytes at offset 0x10118440. It does nothing unless the feature is on. It hides the cursor of every screen but the current one with the method at +8 of the table entry called with zero, puts each screen's saved switch and neighbour words back from its multi-cursor record, sends the cursor-position request with the single-screen command word and the core pointer position (a failure prints the warning that the ioctl failed), and clears the enabled flag. Established.
- `ddxMultiCursorEnable` in `Xsgi`: turns the multi-screen cursor on, 712 bytes at offset 0x1027f5a0. When the multi-cursor generation differs from the server generation it asks the private-record allocator for the per-screen record and stops with the message that initialisation failed when it fails. For each screen it saves the old close method and the old switch method in the screen's record, installs the multi-cursor close hook and cursor-on hook, and records the generation; it then walks the screens calling the method at +8 of each non-current entry, calls the routine that sets the default offsets when the offsets flag is set, and sets the enabled flag. Inferred: the install loop and the flag tests were read, the use of the saved words by later calls is taken from the matching disable routine.

## OpenGL window hooks (read pass 4)

The X server's OpenGL layer wraps five screen methods. Each wrapper takes the GLX screen record that the screen's private array holds (index from a module word), calls the method it saved there with the wrapper's own slot temporarily put back, installs itself again, and then does its one extra step. Every routine below was read to its last instruction.

- `glxWrapCreateWindow` in `Xsgi`: the window-creation hook, 128 bytes at offset 0x1025bd10. It calls the saved creation method at +0x40 of the GLX screen record, re-installs itself in the screen's slot at +0xb4, and clears the window's private pointer for the GLX layer (the slot in the array at +0x84 of the window, indexed by the GLX window private index), so a new window starts with no OpenGL state. It returns the saved method's result. Established.
- `glxWrapDestroyWindow` in `Xsgi`: the window-destruction hook, 188 bytes at offset 0x10254fd0. It calls the saved method at +0x44 of the GLX screen record with its slot at +0xb8 restored, re-installs itself, and, when the window has a GLX private record, releases the two regions held at +0x38 and +0x48 of it through the screen's region-release method at +0x160 and frees the record. It returns the saved method's result. Established.
- `glxWrapPostValidateTree` in `Xsgi`: the hook that runs after the window tree is revalidated, 104 bytes at offset 0x101edcc0. A null window returns at once. Otherwise it calls the saved method at +0x50 of the GLX screen record through the slot at +0xd0, re-installs itself and then calls the routine that rebuilds the server's deep-window list. Established.
- `glxWrapRealizeWindow` in `Xsgi`: the window-map hook, 152 bytes at offset 0x100c8030. It calls the saved method at +0x48 of the GLX screen record through the slot at +0xc4, re-installs itself, and, when the window has a GLX private record, adds the window to the deep-window list. It returns the saved method's result. Established.
- `glxWrapUnrealizeWindow` in `Xsgi`: the window-unmap hook, 152 bytes at offset 0x101f0ca0. It calls the saved method at +0x4c of the GLX screen record through the slot at +0xc8, re-installs itself, and, when the window has a GLX private record, removes the window from the deep-window list. It returns the saved method's result. Established.
